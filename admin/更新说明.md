# 法律科技竞品监控周报站点更新说明

## 每周更新

1. 复制上一期文件，改成新日期文件名，例如：

   `issues/2026-08-19.html`

2. 将新的周报 HTML 内容替换到这个文件中。周报内部的截图、样式和证据链接可以继续保持内嵌，不需要拆分资源。

3. 打开 `data/issues.json`，在数组最前面增加一条记录。除了标题、日期和摘要，还要填写竞品名称和重点动态，首页筛选及“竞品动态索引”依赖这些字段：

   ```json
   {
     "id": "2026-08-19",
     "title": "法律科技产品竞品监控周报",
     "period": "2026/08/12—2026/08/19",
     "periodStart": "2026-08-12",
     "periodEnd": "2026-08-19",
     "publishedAt": "2026-08-19",
     "file": "issues/2026-08-19.html",
     "tags": ["竞品", "行业政策", "法律科技论文", "测评与技术文章"],
     "summary": "用一两句话概括本期重点。",
     "competitors": ["Alpha AI", "幂律智能"],
     "highlights": [
       {
         "competitor": "Alpha AI",
         "action": "本周发生的产品或商业动作",
         "impact": "对产品策略的影响判断",
         "evidence": "S01"
       }
     ]
   }
   ```

4. 首页会自动按照 `publishedAt` 倒序显示最新一期和往期列表，不需要修改 `index.html`。

5. 如果本期有新竞品，直接写入 `competitors`；如果同一竞品有多条动作，可在 `highlights` 中分别列出。

## 本地预览

在 `weekly-report-site` 目录启动静态服务：

```bash
python3 -m http.server 8001 --bind 127.0.0.1
```

然后打开：

`http://localhost:8001/`

单期页面通过以下形式访问：

`http://localhost:8001/view.html?issue=issues/2026-08-19.html`

## 给其他人访问

`localhost` 只对当前电脑可见。若要让其他人通过固定网址访问，需要把整个 `weekly-report-site` 目录部署到静态网站托管服务，例如公司服务器、GitHub Pages、Cloudflare Pages、Netlify 或 Vercel。

部署时使用 `weekly-report-site` 作为网站根目录，入口文件是 `index.html`。以后每周更新 `issues/` 和 `data/issues.json` 后重新发布即可。

## 讨论、报错与统计

- “报告错误”按钮会打开 GitHub Issue 模板，团队可以集中处理页面或内容错误。
- “打开讨论区”使用 GitHub Discussions；如需在页面内嵌评论，按 `README.md` 配置 Giscus。
- GitHub Pages 不提供共享浏览量接口。当前单期页面默认记录每个浏览器的本机次数；需要团队共享总量时，在 `data/site-config.json` 的 `views.apiUrl` 中接入一个带 CORS 的统计接口。
